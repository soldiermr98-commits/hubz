# آزمون‌های خودکار و آفلاین توسعه

این راهنما برای توسعه‌دهنده و ماشین یا کانتینر **مستقل و بدون داده یا اعتبارنامهٔ واقعی** است؛ این دستورات را روی هاست عملیاتی اجرا نکنید. گردش کار پیشنهادی در [`.github/workflows/smoke.yml`](../.github/workflows/smoke.yml) برای PR به `main`، تغییر روی `main` و اجرای دستی تعریف شده است. وضعیت اجرای واقعی آن را در بخش Checks همان commit یا PR ببینید؛ صرف وجود فایل به معنی موفقیت GitHub Actions نیست.

## پوشش و محدودیت‌ها

- **بسته‌ها:** صحت CRC و هش RC1/RC2، بازسازی محتوای پین‌شده و تعارض خروجی، استخراج ساختگی، مانیفست و حفظ فایل‌های ساختگی بررسی می‌شود. برای اشیای Git مربوط به مبنا و مقصد باید تاریخچهٔ کافی وجود داشته باشد؛ workflow عمداً checkout با تاریخچهٔ کامل انجام می‌دهد. RC2 از مبنای `.5` است و وصلهٔ RC1 نیست.
- **پنل:** Node 22، نصب از lockfile، TypeScript، ساخت Vite، تطبیق بایتی JS/CSS ساخته‌شده با بستهٔ پنل و نسخهٔ URL، و تست‌های رابط مالی، گزارش، CSV، Apify، مقاله، AI و رویداد بنر با دادهٔ ساختگی اجرا می‌شوند. این‌ها از jsdom/شبیه‌ساز استفاده می‌کنند، نه مرورگر واقعی و هاست.
- **PHP:** بررسی نحوی تمام فایل‌های PHP ردیابی‌شده و تست‌های واحد با پاسخ، فایل، کلید و PDO ساختگی برای نسخه‌های ۸٫۱ تا ۸٫۵ اجرا می‌شوند. تست رسانه به GD با خواندن/نوشتن WebP، `mbstring`، `fileinfo` و PDO نیاز دارد و منشأ آپلود و DB آن جعلی‌اند. تست پروتکل درگاه فقط کلاس‌های مورد نیاز را مستقیماً بارگذاری می‌کند؛ آزمون جداگانه با تنظیمات مسمومِ ساختگی بررسی می‌کند که به تنظیمات سایت رجوع نشود. تست [ابزار پیش‌بررسی RC2](RC2_READINESS_FA.md) نیز مبنای ساختگی، اختلاف، ورودی دستکاری‌شده، symlink و جلوگیری از دسترسی وب را بررسی می‌کند؛ برای همین مورد آخر یک سرور کوتاه‌عمر فقط روی loopback راه می‌افتد.
- گردش کار اجازهٔ `contents: read` دارد، اعتبار checkout را در مخزن باقی نمی‌گذارد و نسخه‌های action را با SHA پین می‌کند. سیستم‌عامل runner فعلاً `ubuntu-24.04` است؛ actionهای checkout و setup-node از runtime پشتیبانی‌شدهٔ Node 24 استفاده می‌کنند، در حالی که خود پنل با Node 22 ساخته می‌شود. ذخیرهٔ خودکار cache برای بسته‌های npm غیرفعال است. برای دریافت actionها و وابستگی‌های توسعه به GitHub و npm متصل می‌شود، اما هیچ رمز تولید، برنامهٔ کرون، دیتابیس سایت، درگاه یا سرویس AI واقعی را به کار نمی‌گیرد.

**در این workflow دیتابیس واقعی یا حتی MySQL ساختگی، مهاجرت، endpointهای HTTP خود برنامه، آپلود multipart واقعی، سناریوی رقابت مالی، پشتیبان/بازیابی، مرورگر واقعی، امنیت مستقل، پروتکل روز درگاه، سندباکس ارائه‌دهنده و محیط هاست آزموده نمی‌شوند.** موفقیت آن‌ها مجوز استقرار یا دریافت وجه نیست. نسخهٔ ۸٫۱ در ماتریس صرفاً پوشش سازگاری حداقلی است، نه توصیهٔ استفاده از نسخهٔ بدون پشتیبانی امنیتی؛ نسخه و افزونه‌های هاست باید جداگانه ارزیابی شوند.

## اجرای محلی

ابتدا در کپی توسعهٔ جدا و بدون فایل تنظیمات یا کلید واقعی، Node 22، Python 3، Git با تاریخچهٔ کافی و PHP CLI با افزونه‌های لازم را آماده کنید. دستورهای دقیق و فهرست تست‌ها در خود workflow هستند. بخش اصلی به‌شکل زیر است:

```bash
npm ci --no-audit --no-fund
npm run lint
npm run build
# فهرست کامل تست‌های tsx و تطبیق دارایی‌ها: مرحلهٔ frontend در workflow

python3 tests/build_update_candidate_smoke.py
python3 tests/upgrade_candidate_overlay_smoke.py --candidate rc1
python3 tests/upgrade_candidate_overlay_smoke.py --candidate rc2
(cd release-files/after-v2026.11.07.5-rc1 && sha256sum -c SHA256SUMS.txt)
(cd release-files/after-v2026.11.07.5-rc2 && sha256sum -c SHA256SUMS.txt)

# صرفاً تحلیل نحوی است، ولی هیچ‌یک از این تست‌ها را روی نصب واقعی اجرا نکنید.
git ls-files -z -- '*.php' | xargs -0 -n1 php -l >/dev/null
python3 tests/payment_protocol_isolation_smoke.py
python3 tests/rc2_read_only_preflight_smoke.py
HHX_ALLOW_TEST_FIXTURES=1 php tests/media_service_synthetic_smoke.php
# سایر تست‌های PHP بدون DB: مرحلهٔ php در workflow
```

اگر PHP اجرایی نام دیگری دارد، برای تست ایزوله می‌توان `--php /absolute/path/to/php` داد. تست‌ها فقط فایل موقت ساختگی ایجاد می‌کنند، اما نام یا `localhost` به‌تنهایی جدابودن محیط را تضمین نمی‌کند. آزمون‌های جداگانهٔ دیتابیس و HTTP به fixture محافظت‌شده و DB دورریختنی نیاز دارند: [روش آزمون نامزد](UPGRADE_CANDIDATE_TEST_FA.md) و [روش آزمون آپلود](MEDIA_UPLOAD_TEST_FA.md). در انتها فرآیندهای موقت آن آزمون‌های جداگانه را متوقف کنید.
