# تصاویر حامی‌هاب — راهنمای راه‌اندازی (S30)

> **وضعیت استقرار:** کد S30 روی هاست است (تأیید SHA با عیب‌یاب — هات‌فیکس `use` نصب شده و پنل فعال است). آنچه هنوز باقی است: ست‌کردن توکن کولکتور در `collector-remote/config.php`، اجرای PhotoPusher، نصب ورکر تصویر در کلادفلر و تولید hero مقالهٔ S29.

سیستم تصاویر ترکیبی: **کسب‌وکارها → عکس واقعی** (دانلود روی PC مدیر و پوش به هاست) و
**مقاله‌ها → تصویر شاخص تولیدی** با ورکر مستقل Cloudflare. هیچ مایگریشن دیتابیسی لازم نیست.

---

## ۱. عکس واقعی کسب‌وکارها (PhotoPusher روی PC)

منبع عکس‌ها: داده‌های جمع‌آوری‌شدهٔ قبلی داخل `business_sources.raw` — خروجی رایگان آپی‌فای
(`imageUrls` / `images`) و گوسوم (`photo_urls`). هاست هیچ عکسی دانلود نمی‌کند (سیاست S2)؛
دانلود روی PC شما انجام می‌شود و هاست فقط bytes پوش‌شده را فحش MIME و WebP می‌کند.

### راه‌اندازی یک‌باره

1. **توکن کولکتور:** پنل → شهرها و جمع‌آوری → دکمهٔ «تولید/تعویض توکن کولکتور» → کپی
   → در `collector-remote/config.php` (کلید `bearer_token`) بچسبانید.
   (توکن قبلی باطل می‌شود؛ این همان «تعویض سکرت» معلق بود.)
2. **اجرای پس‌گیری** روی PC:

   ```
   php collector-remote/run.php photos --limit=10
   ```

3. هر عکس موفق: تبدیل به WebP سه‌سایز، ثبت در `business_photos` (با `attribution` و
   `source_url` برای dedupe) و **کاور خودکار** اگر کسب‌وکار کاور نداشت.
4. پیشرفت در `collector-remote/storage/photos-progress.json` ذخیره می‌شود؛ اجرای دوباره
   عکس‌های انجام‌شده را رد می‌کند.

### نکته‌ها

- اگر برای منبعی عکسی در raw نباشد (مثلاً مراکزی که با OSM جمع شده‌اند و `photo_urls` ندارند)،
  یکی از این دو راه: یک run آپی‌فای جدید برای همان شهر/دسته بزنید (خروجی رایگان عکس دارد؛
  dedupe خودکار به همان کسب‌وکار وصل می‌شود) یا برای کسب‌وکارهای شاخص آپلود دستی بهتر است.
- نمایش کپشن منبع («عکس: …») زیر عکس گالری صفحهٔ جزئیات، خودکار از ستون attribution می‌آید.
- حقوقی: بازمیزبانی عکس گوگل خاکستری است؛ با کپشن attribution نرم می‌شود. برای ۱۲ کسب‌وکار
  اول هر صفحه، آپلود دستی بهترین گزینه است.

## ۲. تصویر شاخص مقاله با AI (ورکر Cloudflare مستقل)

این ورکر از relay متن کاملاً جدا است (سکرت و دیپلوی مستقل) — روی پایپلاین S29 اثری ندارد.

### نصب ورکر (حدود ۵ دقیقه)

1. کد `deploy/cf-image-worker.js` را در داشبورد کلادفلر: Workers & Pages → Create Worker
   → paste → Deploy.
2. Settings → Variables and Secrets — سه متغیر Secret:
   - `IMAGE_WORKER_SECRET` — رشتهٔ تصادفی طولانی (این در پنل حامی‌هاب ثبت می‌شود)
   - `CF_ACCOUNT_ID` — Account ID از Overview داشبورد
   - `CF_API_TOKEN` — API Token با پرمیشن Account → Workers AI → Edit
3. پنل حامی‌هاب → هوش مصنوعی → کارت «تصویر شاخص مقاله»:
   - نشانی: `https://<worker-name>.<subdomain>.workers.dev/image`
   - سکرت: همان `IMAGE_WORKER_SECRET`
   - تیک فعال‌سازی و تأیید مصرف → ذخیره → «تست با تصویر کوچک واقعی».

### استفاده در ادیتور مقاله

دکمهٔ «تولید تصویر با AI» کنار تصویر اصلی → پرامپت (پیش‌پرشده از عنوان) → تأیید مصرف →
تولید (تا ~۶۰ ثانیه) → تصویر خودکار در کتابخانهٔ رسانه و ست به‌عنوان کاور مقاله.

- ابعاد تولید 1024×576 است و MediaService به سه واریانت ۴۸۰/۸۰۰/۱۲۰۰ تبدیل می‌کند.
- پرامپت انگلیسی نتیجهٔ بهتری می‌دهد؛ لاحق سبک (فوتورئال، بدون متن و واترمارک) خودکار اضافه می‌شود.
- پلن رایگان Workers AI حدود ۱۰٬۰۰۰ neuron در روز می‌دهد (چند ده تصویر).
- تصویر تولیدی «نمادین» است؛ هرگز جای عکس واقعی کسب‌وکار استفاده نشود.
- کاور ست‌شده با ذخیرهٔ مقاله ثبت می‌شود؛ در انتشار، همان تصویر `og:image` صفحهٔ مقاله است.

## ۳. og:image صفحه‌محور (S30)

- صفحهٔ کسب‌وکار: کاور (800px) → در نبودش لوگوی کارت.
- صفحهٔ مقاله: کاور مقاله → در نبودش لوگوی کارت.
- بقیهٔ صفحات: لوگوی کارت (مثل قبل).
- فقط مسیرهای `/uploads/...` معتبر پذیرفته می‌شوند (همان whitelist اسکیما).

## ۴. تست‌ها

- `tests/public_catalog_smoke.php` — شامل assertion og:image کاور.
- `npm run lint && npm run build:deploy` — پنل.
